Unit 4: Masonry Layouts

Variable-height content

Understanding masonry layouts

A masonry layout keeps strict columns but packs items upward when their heights are different. I built a few versions below to compare the tradeoffs.

The problem

A standard grid leaves gaps

CSS Grid is great when rows should line up, but the tallest card controls each row. The empty space below shorter cards is the gap masonry tries to remove.

Longer explanation

Variable-height content makes the difference easier to see. A regular grid keeps every item aligned to shared row tracks, which creates empty areas.

The old CSS-only workaround

CSS columns pack tightly

column-count makes this look like masonry, but content flows down one column before moving to the next. That can make the visual order and keyboard reading order feel disconnected.
